# Mac Batch OCR — Swift CLI Design Spec

**Date:** 2026-08-09
**Status:** Approved for implementation
**Supersedes:** nothing (new track; `process_image.scpt` remains as legacy)

> **Note:** This file did not exist when requested for review; it was created from the
> current repo state (`README.md`, `process_image.scpt`) and is the baseline spec.

## 1. Goal

Replace the single-image AppleScript OCR helper with a native Swift CLI (`batch-ocr`) that
OCR-processes images and directories in batch using the Apple Vision framework, with full
flag parity with `process_image.scpt` plus recursion, concurrency, output routing, and
structured exit codes.

## 2. Non-Goals

- No GUI, no menu-bar app, no daemon.
- No PDF/multi-page support (images only).
- No third-party OCR engines; Vision only.
- No notarization/distribution packaging beyond a local release build.

## 3. Assumptions (recorded, reasonable defaults)

1. **Spec created, not reviewed** — the requested file did not exist; this document is new.
2. **Toolchain:** Swift 6.x (verified locally: 6.3.3, macOS 26). Tests use **Swift Testing**
   (bundled with Swift 6); no XCTest requirement.
3. **Platform floor:** macOS 13 (Ventura) — gives `VNRecognizeTextRequest` revision 3.
4. **Single external dependency:** `apple/swift-argument-parser` (>= 1.3.0). Everything else
   is Foundation/Vision/Concurrency stdlib — this is the deliberate codebase-minimization rule.
5. **Language codes** are passed to Vision verbatim (BCP-47 style: `en-US`, `pt-BR`). The
   legacy ISO-639-1 default `en` remains valid input.
6. **No binary fixtures in git** — tests render text images at runtime via CoreGraphics.
7. **Agents' graph** = the JSON status file `.agent/status.json` (schema in §7). No external
   tracker integration is assumed.
8. Output default stays parity-compatible: `<image-name>.txt` next to the source image.

## 4. Tech Stack

| Concern        | Choice                                        | Why |
|----------------|-----------------------------------------------|-----|
| Package        | SwiftPM executable target `batch-ocr`         | Zero-install toolchain build |
| CLI parsing    | `apple/swift-argument-parser`                 | Removes all hand-rolled arg code (verified via Context7) |
| OCR            | `Vision.VNRecognizeTextRequest` (accurate)    | Same engine as legacy script, native |
| Concurrency    | Swift structured concurrency (`TaskGroup`)    | Stdlib only |
| Tests          | Swift Testing + CoreGraphics fixture renderer | No committed binaries |
| Logging        | Minimal leveled logger (stderr + optional file) | No logging framework needed |

## 5. CLI Contract

```
batch-ocr [options] <paths...>
```

| Option | Meaning | Default |
|---|---|---|
| `<paths...>` | Image files and/or directories (positional, 1+) | required |
| `-d, --detect-language` | Vision auto language detection | off (parity) |
| `-l, --language <code>` | Recognition language(s), repeatable | `en` (parity) |
| `-c, --language-correction` | Vision language correction | off (parity) |
| `-o, --output-dir <dir>` | Write all `.txt` here (created if missing) | beside each image |
| `-r, --recursive` | Recurse into subdirectories | off |
| `-j, --jobs <n>` | Max concurrent OCR tasks | 4 |
| `--extensions <csv>` | Image extensions to include | `png,jpg,jpeg,tif,tiff,heic,webp` |
| `--overwrite` | Re-OCR even if `.txt` exists | off (skip) |
| `--log-file <path>` | Also append log lines to file | none |
| `-q, --quiet` | Suppress per-file progress | off |
| `-v, --version` | Print version | — |
| `-h, --help` | Generated by ArgumentParser | — |

**Exit codes:** `0` all processed; `1` batch finished with per-file failures; `2` usage/config error.

**Parity mapping (legacy → new):** `-h/--help` → `--help`; `-d` → `-d`; `-l X` → `-l X`;
`-c` → `-c`; single image arg → `<paths...>`; `find ... -exec` batch recipe → native
directory argument (README must show the new one-liner).

## 6. File Structure

```
Package.swift                              # tools 6.0, platforms .macOS(.v13), dep: swift-argument-parser
Sources/BatchOCR/
  BatchOCRCommand.swift                    # @main ParsableCommand; maps args -> OCRConfig; exit codes
  OCRConfig.swift                          # value type: languages, correction, detect, jobs, overwrite, outputDir...
  OCREngine.swift                          # Vision wrapper: recognize(imageURL:config:) throws -> String
  FileDiscovery.swift                      # paths -> [URL] (extension filter, recursion, dedupe)
  BatchProcessor.swift                     # TaskGroup runner, skip logic, per-file result enum
  Reporter.swift                           # progress lines, summary, leveled log (stderr + file)
Tests/BatchOCRTests/
  FixtureFactory.swift                     # CoreGraphics text-image renderer (shared helper)
  OCREngineTests.swift
  FileDiscoveryTests.swift
  BatchProcessorTests.swift
  CommandConfigTests.swift
.agent/status.json                         # agent graph status (created at runtime, gitignored)
```

Design rules: `OCREngine` and `BatchProcessor` take protocols/values so tests can inject a
mock engine; `BatchOCRCommand` contains no OCR logic (thin mapping layer only).

## 7. Agent Execution Contract (loops + graph reporting)

Each milestone is one agent loop:

```
read entry criteria -> implement scope -> run every DoD check -> write report -> follow "Next"
```

**Report:** after each milestone the agent MUST update `.agent/status.json`:

```json
{
  "project": "mac-batch-ocr-swift",
  "updated_at": "<ISO-8601>",
  "current": "M1",
  "history": [
    {
      "milestone": "M0",
      "status": "done | blocked",
      "dod": [{"id": "M0-1", "command": "swift build", "pass": true}],
      "next": "M1",
      "notes": ""
    }
  ]
}
```

Rules:
- `status: done` requires **every** DoD entry `pass: true`; then `next` = the milestone named
  in the spec's **Next** field.
- On failure: fix and re-loop within the same milestone. If still blocked after 3 attempts,
  set `status: blocked`, `next: "human-review"`, and put the failing command + error in `notes`.
- Never start milestone M(n+1) before M(n) is `done`.
- `.agent/` is added to `.gitignore`; reports are runtime artifacts, not source.

**Milestone graph:** `M0 -> M1 -> M2 -> M3 -> M4 -> M5 -> END` (linear; blocked edges go to
`human-review`).

## 8. Global Constraints

- macOS 13+; Swift tools 6.0; arm64 + x86_64 must both build (`swift build` on Apple Silicon is sufficient for CI-less dev).
- Exactly one external dependency: `swift-argument-parser`. Adding another requires a spec change.
- No comments in code unless documenting a non-obvious Vision/API quirk.
- Every milestone ends with a commit; commit messages follow existing repo style (short imperative).
- Legacy `process_image.scpt` is not modified or deleted by any milestone.

### M1 — OCR Engine (Vision wrapper)

**Entry criteria:** M0 done.

**Scope:**
- `OCRConfig.swift`: `languages: [String] = ["en"]`, `usesLanguageCorrection: Bool`, `automaticallyDetectsLanguage: Bool`.
- `OCREngine.swift`: `func recognize(imageURL: URL, config: OCRConfig) throws -> String` using
  `VNRecognizeTextRequest` (`recognitionLevel = .accurate`, latest supported revision,
  `recognitionLanguages`, `usesLanguageCorrection`, `automaticallyDetectsLanguage`); join
  candidates with `\n`; throw typed `OCRError` (`fileNotFound`, `unreadableImage`, `visionFailed(underlying:)`).
- `FixtureFactory.swift`: render a given string into a PNG at a temp URL using CoreGraphics
  (white bg, black system font >= 48pt).

**Definition of Done:**
| ID | Check | Command | Expected |
|---|---|---|---|
| M1-1 | Happy path | `swift test --filter OCREngineTests` | fixture rendered with `BATCH OCR 2026` is recognized; result contains that string |
| M1-2 | Missing file | same filter | nonexistent URL throws `OCRError.fileNotFound` |
| M1-3 | Full suite | `swift test` | exit 0 |
| M1-4 | Release build | `swift build -c release` | exit 0 |
| M1-5 | Commit | `git log -1 --oneline` | engine commit present |

### M2 — CLI Wiring + Legacy Parity

**Entry criteria:** M1 done.

**Scope:**
- Map ArgumentParser options → `OCRConfig` in `BatchOCRCommand.run()`; process a single file path end-to-end (batch discovery comes in M3 — for now accept exactly one existing file and reject directories with exit 2).
- Write `<stem>.txt` beside the image (UTF-8, overwrite).
- Exit codes per §5.

**Definition of Done:**
| ID | Check | Command | Expected |
|---|---|---|---|
| M2-1 | Single file | `swift run batch-ocr <fixture.png>` | exit 0; `<fixture>.txt` exists and contains fixture text |
| M2-2 | Flags accepted | `swift run batch-ocr -d -l en -l pt-BR -c <fixture.png>` | exit 0; same output file produced |
| M2-3 | Usage error | `swift run batch-ocr` (no args) | exit 2 (ArgumentParser error), usage on stderr |
| M2-4 | Bad path | `swift run batch-ocr /nonexistent.png` | exit 2, clear message |

### M3 — Batch Discovery + Output Routing

**Entry criteria:** M2 done.

**Scope:**
- `FileDiscovery.swift`: expand `paths` (files kept as-is; directories enumerated with/without recursion per `-r`), filter by `--extensions` (case-insensitive), dedupe, sort for deterministic order.
- Output routing: default beside image; `--output-dir` mirrors file names into target dir (created if missing; name collisions from different dirs are out of scope — note in README).
- Skip logic: existing non-empty `.txt` → skip unless `--overwrite`; skipped files count in summary, not failures.
- Per-file isolation: one file throwing never aborts the batch; failures collected.

**Definition of Done:**
| ID | Check | Command | Expected |
|---|---|---|---|
| M3-1 | Discovery tests | `swift test --filter FileDiscoveryTests` | recursive vs non-recursive, extension filter, dedupe all pass on a temp dir tree |
| M3-2 | Output routing tests | `swift test --filter BatchProcessorTests` | beside-image and `--output-dir` naming + skip/overwrite behavior pass (mock engine) |
| M3-3 | Integration | run release binary on a temp dir with 3 fixture images, one zero-byte `.png` | 3 `.txt` created; zero-byte file reported failed; exit 1 |
| M3-4 | Idempotency | re-run same command | 3 skips, 1 failure, no rewrites (mtime unchanged); exit 1 |
| M3-5 | Full suite | `swift test` | exit 0 |
| M3-6 | Commit | `git log -1 --oneline` | batch commit present |

**Next:** `M4`

### M4 — Concurrency, Progress, Logging

**Entry criteria:** M3 done.

**Scope:**
- `BatchProcessor` runs via `TaskGroup` capped at `--jobs` (validate `jobs >= 1`, else exit 2).
- `Reporter`: `[i/N] ok|skip|fail <path>` per file (suppressed by `-q`), final summary
  `done=X skipped=Y failed=Z elapsed=Ns`, leveled log lines (`INFO/WARN/ERROR`) to stderr and
  optionally `--log-file` (append, timestamped — format compatible with legacy `process_image_log.txt`).
- Engine is Sendable-safe; no shared mutable state between tasks.

**Definition of Done:**
| ID | Check | Command | Expected |
|---|---|---|---|
| M4-1 | Concurrency cap | test with mock engine counting in-flight tasks, `jobs=2`, 8 items | max observed in-flight <= 2 |
| M4-2 | Thread safety | `swift test --sanitize=thread` | exit 0, no race reports |
| M4-3 | Progress + summary | run on 10 fixtures with `-j 4` | 10 progress lines + summary counts correct |
| M4-4 | Quiet | same run with `-q` | no per-file lines; summary still printed |
| M4-5 | Log file | same run with `--log-file out.log` | `out.log` contains one timestamped entry per file + summary |
| M4-6 | Commit | `git log -1 --oneline` | concurrency commit present |

## 9. Risks

| Risk | Mitigation |
|---|---|
| Vision recognition is nondeterministic across macOS versions | Tests assert `contains` on high-contrast rendered fixtures, not exact equality |
| `--output-dir` name collisions across nested dirs | Documented as out of scope; last-write-wins |
| HEIC/WebP support varies by macOS minor version | Discovery filters by extension only; unreadable files fail per-file (exit 1), never crash |
| Swift Testing unavailable on older contributor toolchains | Spec pins Swift 6 floor; README states requirement |
